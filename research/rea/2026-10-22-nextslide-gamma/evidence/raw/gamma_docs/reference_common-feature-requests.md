# API scope and limits

What the Gamma API and MCP server cover today — generate, edit, read, export, and analyze gammas — and the limits to design around.

The Gamma API and the hosted MCP server let your code or your AI agent generate new gammas, edit existing ones, read their content and comments, export them to PDF, PPTX, or PNG, and read engagement analytics. This page is the one-screen map of that surface and the limits to design around.

### Quick reference

* Generate new presentations, documents, and social posts with the Gamma 5 agent (`POST /agent/generations`, optionally from a template or existing gamma via `templateId`). This is the recommended path for new integrations. The Classic endpoints (`POST /generations`, `POST /generations/from-template`) run the previous engine, remain available for existing integrations, and are the way to generate webpages and multi-page gammas or sites.
* Edit an existing gamma: `POST /agent/gammas/{gammaId}/edits` applies a natural-language instruction to a gamma you can edit. The MCP server exposes the same capability as `edit_gamma`.
* Read existing gammas: metadata, full-text search, comment threads, and analytics. The MCP `read_gamma` tool returns a gamma's content.
* Export any gamma in your workspace that you can view, not just ones the API created (`POST /gammas/{gammaId}/export`). Gammas from other workspaces and archived gammas can't be exported.
* Everything that generates, edits, or exports is asynchronous: create the job, then poll until `completed` or `failed`. There are no webhooks.
* Export URLs are temporary -- download files promptly.
* Image URLs in your input must be publicly accessible.
* Archiving does not deduct credits. Deletion is available to workspace admins.
* Submit feature requests on our [Canny board](https://meetgamma.canny.io).

### Limits to design around

**Editing.** Edits apply to the gamma you point at and cannot add new pages; to add content beyond that, generate a new gamma. The caller needs edit access to the gamma, archived gammas cannot be edited, and only one edit runs on a gamma at a time. Edits are prompt-directed: you describe the change in natural language and Gamma applies it. There is no object-level API for addressing a specific slide element.

**Templates.** `POST /generations/from-template` and `generate_from_template` accept gammas in your workspace that are marked as templates. The template must be single-page, with a card count within your plan's card limit; non-template, archived, multi-page, and site-bound gammas are rejected when you submit the request. Official Explore templates from `GET /templates/search` are not accepted as `gammaId`, but are accepted as `templateId` on the agent endpoint. The template's structure is preserved by default and changes only when your prompt asks for it. See [Generate from template](/guides/create-from-template-api-parameters-explained.md). The agent endpoint is broader: `POST /agent/generations` takes an optional `templateId` naming a workspace template, an existing gamma in the workspace, or an official Explore template, and the prompt decides how that source is used.

**Charts and structured content.** Charts, tables, and infographics can be prompted for, but there are no parameters that control chart type, styling, or data formatting, and results vary across runs. For predictable layouts, build them into a template. See [Charts and structured content](/guides/charts-and-structured-content.md).

**Exports.** A completed generation includes an `exportUrl` when you set `exportAs`; any other gamma in your workspace that you can view can be exported with `POST /gammas/{gammaId}/export` (archived gammas can't). `pdf` and `pptx` download directly; `png` returns a `.zip` with one PNG per card. Export URLs expire after approximately one week, and anyone with the link can download the file until then -- treat them as secrets.

**Your own images.** On the Classic endpoints, include image URLs in `inputText` (`POST /generations`) or `prompt` (`POST /generations/from-template`); Gamma fetches and re-hosts them. See [Image URL best practices](/guides/image-url-best-practices.md) for URL requirements. `POST /agent/generations` doesn't guarantee that URLs in `prompt` are fetched and re-hosted.

**Waiting for results.** Poll the matching status endpoint every few seconds. See [Poll for results](/guides/async-patterns-and-polling.md) for implementation patterns.

For example, with `ask=how do I create an API token`, a goal like `automate deployments from our CI pipeline` lets GitBook tailor the answer to that use case.

The response will contain a direct answer to the question and relevant excerpts and sources from the documentation.
